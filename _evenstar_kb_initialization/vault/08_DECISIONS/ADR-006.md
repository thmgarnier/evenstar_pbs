# ADR-006 — Initial Supabase / PostgreSQL canonical backbone

## Context

PBS source explicitly selects an initial shared canonical collaboration/data backbone; PSS/PMS describe shared identity/base mappings.

## Decision

Use Supabase/PostgreSQL as the initial PBS canonical backbone and shared Evenstar identity/integration-registry direction.

## Consequences

Keep schemas/data portable. Supabase Auth, storage and realtime remain candidates; this decision does not place solver internals or all PMS data in one universal database.

## Alternatives

Different infrastructure may be substituted later through an explicit decision while preserving domain models/contracts.

Alternatives here are curator analysis, not a claim that a historical options review occurred.
